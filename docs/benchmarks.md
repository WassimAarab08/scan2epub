# Benchmarks

The numbers in this page are produced by `scan2epub eval`, which measures the
**Character Error Rate** (CER) and the **Word Error Rate** (WER) of every
engine against a reference transcription.

> **Status: Phase 2.**
>
> The evaluation corpus, the `eval` command and the table below are part of
> Phase 2. This page documents the methodology so that the numbers are
> reproducible when they arrive.

## The metrics

| Metric | Definition | Range |
| --- | --- | --- |
| **CER** | The Levenshtein distance between the hypothesis and the reference, divided by the length of the reference, over the whole corpus. | `0.0` is perfect, `1.0` is completely wrong. |
| **WER** | The same, but the text is split into words first. | idem |

Both are computed with [`jiwer`](https://github.com/jitsi/jiwer) (MIT), over
the concatenation of the pages of a book, so that a page boundary does not
inflate the score.

## The methodology

| Aspect | Choice | Reason |
| --- | --- | --- |
| The reference | A human transcription of the same pages, with the running heads and the folios removed. | The same normalisation the cleaner applies, so the measurement isolates the *recognition*. |
| The normalisation | NFKC, lower case, the punctuation removed, the whitespace squeezed. | The typography of the reference and of the hypothesis differ; only the words must match. |
| The corpus | 10 to 20 pages of books of the 18th and 19th centuries, in Spanish and in English, with their provenance in `SOURCE.md`. | Small enough to run in the CI in a couple of minutes. |
| The measurement | The whole book at once, not page by page. | A page-by-page score hides the errors that the cleaner repairs. |

The two numbers answer different questions:

- The **CER** measures the characters. It is the right number for a historical
  book, where the long s and the ligatures are the main source of error.
- The **WER** measures the words. It is the right number for a modern book.

## What we expect

The order below is what the literature and the first experiments suggest. The
numbers will be confirmed by the evaluation.

| Engine | CER | WER | Notes |
| --- | --- | --- | --- |
| `tesseract` (modern Spanish) | the highest | the highest | It does not know the long s. |
| `tesseract` (`spa_old`) | lower | lower | The legacy language data knows the historical spellings. |
| `paddleocr-vl` | lower | lower | A vision-language model reads the long s as a long s. |
| `teleocr` | lower | lower | Comparable to PaddleOCR-VL, heavier. |
| `litellm` (a remote vision model) | the lowest | the lowest | The best recognition, at a price. |
| Any engine + the LLM corrector | lower | lower | The correction never makes the score worse: the guardrail rejects the changes that drift too far. |

The last row is the important one: the corrector is **not** trusted, so the
CER and the WER after the correction can only be equal or better than before.

## Reproducing the numbers

```bash
uv sync --all-extras
uv run python scripts/fetch_samples.py      # the public-domain corpus
uv run scan2epub eval \
    --samples samples/ \
    --ocr tesseract \
    --ocr paddleocr-vl \
    --markdown docs/benchmarks.md
```

The evaluation runs in the continuous integration on a small subset, so a
regression in the recognition is caught by a pull request.

## The hardware

The speed column depends a lot on the hardware. The reference machine for the
published numbers is:

| | |
| --- | --- |
| CPU | AMD Ryzen 9 7950X, 16 cores |
| GPU | NVIDIA RTX 4090, 24 GiB |
| RAM | 64 GiB |
| Software | CUDA 12.4, PyTorch 2.6, Tesseract 5.5 |

Tesseract is single threaded per page; the vision models need the GPU.
